## ここまでで使えるようになったコマンド

| コマンド | 用途 |
|---|---|
| `git init` | リポジトリを作る |
| `git status` / `--short` | 3つのエリアの状態を見る |
| `git add ファイル名` | ワークツリー → ステージ |
| `git restore --staged .` | ステージから降ろす（addの取り消し） |
| `git restore ファイル名` | ワークツリーの変更を捨てる（戻せない） |
| `git commit -m` | 履歴に記録する |
| `git log` / `--oneline` | 履歴を見る |
| `git diff` | ワークツリー vs ステージ |
| `git diff --staged` | ステージ vs 最後のコミット |
| `git remote add origin` / `git remote -v` | リモートを登録・確認 |
| `git push -u origin main` / `git push` | ローカル → GitHub |
| `git pull` | GitHub → ローカル |

## つまずいたこと

### zsh のヒストリ展開（3回連続で事故）

ダブルクォート内の `!!` が「直前に実行したコマンド」に置換され、ファイルの中身が壊れた。
**文字列はシングルクォートで囲む。**

```
echo "hello!!"     → 直前のコマンドが混入して壊れる
echo 'hello!!'     → そのまま出力される
```

### 複数行のまとめ貼り付け

ターミナルに複数行を一度に貼ると、前のコマンドが混入する事故が起きた。**1行ずつ実行して毎回出力を確認する。**

### `git add .` で秘密情報がステージに乗った（2回）

1回目はコマンドで、2回目はエディタのGUIボタンで。いずれもコミット前に `git restore --staged .` で回復。
Day07 の `.gitignore` で構造的に解決した。

### GUIボタンは中身が見えない

「コミットしてプッシュ」は ステージ → コミット → プッシュ を一息に実行するため、途中で止まってもどこまで進んだか画面から読めない。
**操作はターミナル、確認だけGUI**という方針にした。

## この月で一番大きかった学び

**Gitで事故るのは「まとめて」やったとき。1つずつ選べば事故らない。**

そして事故そのものより、**戻し方を知っているかどうか**が効いた。
`git restore --staged` を4回、`git restore` を2回使って、いずれも無傷で復旧できた。
コミット前なら大抵のことは取り返しがつく。
