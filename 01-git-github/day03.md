# Day 03 — git init・status・add・commit（2026-08-19）

## やったこと
- 練習用リポジトリを `git init` で作成
- `.git` の中身（`HEAD` / `objects/` / `refs/`）を確認
- ファイルを5つ作り、`git status` の3つの見出しを実機で確認
- **5ファイル中2ファイルだけ**を選んでコミット（ステージングの粒度）
- 意味ごとに分けた3つのコミットを `git log --oneline` で確認

## わかったこと
- `git status` の見出しが、そのままファイルのいる場所を表している

| 見出し | エリア |
|---|---|
| `Untracked files:` | ワークツリー（Gitが一度も見ていない） |
| `Changes not staged for commit:` | ワークツリー（Gitが知っている） |
| `Changes to be committed:` | ステージ |

- `--short` の2文字は **左＝ステージ / 右＝ワークツリー**。`MM` は両方に変更がある状態
- **`git add` は「登録」ではなく「その瞬間の中身をステージにコピーする」動作。** だから add 後に編集すると、同じファイルが2つの状態で同時に存在する（`MM`）。この状態でコミットすると**ステージ側**が記録される
- 一度コミットしたファイルは、以後 `Untracked` には戻らない

## つまずき
- **zshの `!!` で3回連続で事故。** ダブルクォート内の `!!` が「直前に実行したコマンド」に置換され、ファイルの中身が壊れた → **文字列はシングルクォートで囲む**
- 複数行をまとめて貼り付けたことで、前のコマンドが混入した → **1行ずつ実行する**
- **`git add .` で `.env`（ダミーの秘密情報）がステージに乗った。** コミット前に気づき `git restore --staged .` で回復
- `git add .` は Day07 の `.gitignore` を書くまで封印すると決めた
